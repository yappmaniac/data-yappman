# Index publish-day checklist (UK and AU shelf-price index pages)

Done by the Data Website session in the same push as the weekly figures, after the weekly vintage is in the public dataset.

- [ ] `dateModified` in the Dataset JSON-LD on `/shelf-price-index/` and `/au-shelf-price-index/` is set to the publish date (yyyy-mm-dd). Check it parses: `node` over the page's `application/ld+json` blocks, or the site's structured-data check.
- [ ] `docs/release/stamp-latest.js` run and `--check` clean.
- [ ] UK: `docs/release/build-index-files.js --uk FILE --confirm-uk <week>` run with the same JSON file as the stamp (its .csv beside it). It adds the week to `data/uk-shelf-price-index.csv` and `.json` and rewrites `data/uk-shelf-price-index-headline.json`.
- [ ] AU: `docs/release/build-index-files.js --au FILE --confirm-au <week>` run with the same JSON file as the stamp (its .csv beside it). It adds the week to `data/au-shelf-price-index.json`.
- [ ] `docs/release/build-endpoints.js` run after build-index-files.js, and `build-endpoints.js --check` clean: it refreshes data/v1/ (the stable copies of the index files and manifest.json); the files go in the SAME commit.
- [ ] `docs/release/build-category-pages.js` run after build-index-files.js (it reads data/uk-shelf-price-index.json) and `build-category-pages.js --check` clean: it rewrites the 17 pages under shelf-price-index/categories/; they go in the SAME commit, and `set-lastmod.js` covers their sitemap dates.
- [ ] `docs/release/build-cpi-page.js` run after the index files, and `--check` clean (it rewrites /shelf-price-index/vs-cpi/ with the latest weeks). When ONS or ABS publish a new CPI month, update data/cpi-reference.json by hand from their release pages (value, month, publication date, link, retrievedOn) and rebuild.
- [ ] `docs/release/build-moves-feed.js` run after the index files, and `--check` clean: it rewrites shelf-price-index/moves.xml (Atom) with the new week; same commit.
- [ ] `docs/release/build-coverage-page.js` run after the index files, and `--check` clean: it rewrites /coverage/ (weeks held, by retailer) from the index files and data/coverage-reference.json. A normal week needs no edit; a new gap in a retailer's snapshots, or a claim not yet confirmed (shown as a dash until it has a source), is a hand edit of data/coverage-reference.json with a source; same commit.
- [ ] `docs/release/build_staples.py --check` clean (it needs no inputs). To add basket days, rerun `build_staples.py --basket CSV --staples uk-staples.json` with the SAME `--min-products` and `--min-days` as the files' `definition` records (a change of either number is a decision for Russell); both `data/staples-weekly.json` and `data/staple-price-moves-weekly.json` go in the SAME commit.
- [ ] `docs/release/build-freshness.js` run after the index files (it reads data/uk-shelf-price-index-headline.json and data/au-shelf-price-index.json) and `build-freshness.js --check` clean; data/freshness.json and badges/*.svg go in the SAME commit. It stops on a missing, future or older-than-21-days week.
- [ ] `docs/release/build-index-files.js --check` clean. The index pages, the home page and `/press/` read these files and never call the dataset, so a week that is stamped but not added here would leave the page showing the week before; `--check` fails on that. The data files go in the SAME commit as the stamp.
- [ ] `docs/release/set-lastmod.js` run for the pages that changed (sitemap `lastmod`).
- [ ] Wording lint: 0 errors.
- [ ] After the push: IndexNow run succeeded and its log lists every HTML page the push changed (`git diff --name-only <last pinged commit> HEAD -- '*.html'`; docs/release/indexnow-base.js picks the base); the live pages carry the new dates. A manual run takes `base` = the commit to compare with.
