# Index publish-day checklist (UK and AU shelf-price index pages)

Done by the Data Website session in the same push as the weekly figures, after the weekly vintage is in the public dataset.

- [ ] `dateModified` in the Dataset JSON-LD on `/shelf-price-index/` and `/au-shelf-price-index/` is set to the publish date (yyyy-mm-dd). Check it parses: `node` over the page's `application/ld+json` blocks, or the site's structured-data check.
- [ ] `docs/release/stamp-latest.js` run and `--check` clean.
- [ ] UK: `docs/release/build-index-files.js --uk FILE --confirm-uk <week>` run with the same JSON file as the stamp (its .csv beside it). It adds the week to `data/uk-shelf-price-index.csv` and `.json` and rewrites `data/uk-shelf-price-index-headline.json`.
- [ ] AU: `docs/release/build-index-files.js --au FILE --confirm-au <week>` run with the same JSON file as the stamp (its .csv beside it). It adds the week to `data/au-shelf-price-index.json`.
- [ ] `docs/release/build-endpoints.js` run after build-index-files.js, and `build-endpoints.js --check` clean: it refreshes data/v1/ (the stable copies of the index files and manifest.json); the files go in the SAME commit.
- [ ] `docs/release/build-category-pages.js` run after build-index-files.js (it reads data/uk-shelf-price-index.json) and `build-category-pages.js --check` clean: it rewrites the 17 pages under shelf-price-index/categories/; they go in the SAME commit, and `set-lastmod.js` covers their sitemap dates.
- [ ] `docs/release/build-cpi-page.js` run after the index files, and `--check` clean (it rewrites /shelf-price-index/vs-cpi/ with the latest weeks). When ONS or ABS publish a new CPI month, update data/cpi-reference.json by hand from their release pages (value, month, publication date, link, retrievedOn) and rebuild.
- [ ] `docs/release/build-moves-feed.js` run after the index files, and `--check` clean: it rewrites shelf-price-index/moves.xml (Atom) with the new week; same commit.
- [ ] `node docs/release/site-template.js --check` clean: the menu and footer of every page come from `_template/` (edit `_template/nav.tpl` or `_template/footer.tpl`, never a page, then run `node docs/release/site-template.js --write`; a page's own legal note sits between its `<!-- site:notes -->` markers and is never rewritten). The four page builders (categories, CPI, coverage, basket) copy the menu through the same source, so a menu change needs their `--check` clean too.
- [ ] `node docs/release/check-site-size.js --git` before every push: the served tree is under 600 MB (it warns from 600 MB and fails from 900 MB; GitHub Pages allows 1 GB). Keep the latest data vintage plus one year-end vintage and delete older ones from the tree.
- [ ] `node docs/release/check-dataset-ld.js` clean: every data page carries one true Dataset block (licence URL as the page states it, only files that exist, no affiliate parameter). A new data page or sample is added to REQUIRED in that script in the same change; the category pages get theirs from `build-category-pages.js`.
- [ ] `docs/release/build-coverage-page.js` run after the index files, and `--check` clean: it rewrites /coverage/ (weeks held, by retailer) from the index files and data/coverage-reference.json. A normal week needs no edit; a new gap in a retailer's snapshots, or a claim not yet confirmed (shown as a dash until it has a source), is a hand edit of data/coverage-reference.json with a source; same commit.
- [ ] Basket check (/basket/): `docs/release/build-basket-pilot.js --check` and `build-basket-page.js --check` clean. The daily file data/basket-pilot.json is rebuilt by the basket-pilot-sync workflow (one capped read of the pilot dataset; off until BASKET_PILOT_SYNC_ENABLED is true); a change to the pinned list (data/basket-pilot-list.json, by a person, with its checkedOn date) needs a rebuild of the page and a new item number only for a NEW item (numbers are never reused).
- [ ] Basket check, a shop asks us in writing to stop. Do it the day the message is read. (1) `node docs/release/basket-remove-shop.js SHOP` (aldi, asda, sainsburys or tesco): it sets `removedShops` in data/basket-pilot-list.json and takes that shop's product entries (name, id, link, pack size) out of it, takes the shop's cells out of data/basket-pilot.json, and rebuilds basket/index.html. (2) `git diff --stat`: those three files only. Commit. (3) Run the gates on a CLEAN CHECKOUT of that exact commit (an extracted `git archive` of the commit id), never on the working tree; the gates pass with a shop removed. (4) Push that commit id (`git push origin <commit id>:refs/heads/main`, fast-forward only), never the working tree or a branch name; Russell pre-approved this push for the basket page on 17 Nov 2026 and the Orchestrator relays it, naming the shop. (5) The Orchestrator stops the daily collection for that shop the same day. The page then names the shop only as not in the comparison, with no reason given. At least two shops must stay. `--restore SHOP` reopens the column only: the product entries come back when a person regenerates the list with `make_basket_pilot_list.py` (which keeps a removed shop out until then), each on Russell's own go.
- [ ] `docs/release/check-affiliate-disclosure.js` clean. Links to our own Actor pages in page content carry `?fpr=wy5pu7` (after any utm tags) and `rel="sponsored"`, and their page carries the standard disclosure line (docs/release/affiliate.js holds the token, rel and text). Never in the menu, llms.txt, data/*.txt or structured data. A new page with an Actor link: use `affiliate.js` in its builder, or add the parameter, rel and disclosure by hand; the check fails if one is missing.
- [ ] `docs/release/build_staples.py --check` clean (it needs no inputs). To add basket days, rerun `build_staples.py --basket CSV --staples uk-staples.json` with the SAME `--min-products` and `--min-days` as the files' `definition` records (a change of either number is a decision for Russell); both `data/staples-weekly.json` and `data/staple-price-moves-weekly.json` go in the SAME commit.
- [ ] Driving test waits (/driving-test-wait-index/, monthly, from the second Wednesday): `python -I -B docs/release/check_driving_test_freshness.py` clean (exit 0: the published release is under 45 days old and the page states the same month and release as the files); `python -I -B docs/release/fetch_driving_test_waits.py --status` is the one-request check of whether DVSA has published a newer release (it saves nothing); a new vintage is fetched and built only on a typed go that names it (`fetch_driving_test_waits.py --fetch`, then `driving_test_waits_site.py --check`, then `--publish`).
- [ ] `docs/release/build-freshness.js` run after the index files (it reads data/uk-shelf-price-index-headline.json and data/au-shelf-price-index.json) and `build-freshness.js --check` clean; data/freshness.json and badges/*.svg go in the SAME commit. It stops on a missing, future or older-than-21-days week.
- [ ] `docs/release/build-index-files.js --check` clean. The index pages, the home page and `/press/` read these files and never call the dataset, so a week that is stamped but not added here would leave the page showing the week before; `--check` fails on that. The data files go in the SAME commit as the stamp.
- [ ] `docs/release/set-lastmod.js` run for the pages that changed (sitemap `lastmod`).
- [ ] Wording lint: 0 errors.
- [ ] After the push: IndexNow run succeeded and its log lists every HTML page the push changed (`git diff --name-only <last pinged commit> HEAD -- '*.html'`; docs/release/indexnow-base.js picks the base); the live pages carry the new dates. A manual run takes `base` = the commit to compare with.
